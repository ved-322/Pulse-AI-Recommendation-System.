The AI

A hybrid recommender with three signals

score(item) = w₁·Content + w₂·Collaborative + w₃·Popularity
weights are set by the admin, normalised to 100%, and applied immediately

1 · Content-based

Builds a profile of your categories and topics from what you chose and what you did (recency-decayed). Scores items sharing those features.

default weight 50%

2 · Collaborative

Finds the 10 users most similar to you (cosine similarity) and recommends what they loved that you have not seen.

default weight 30%

3 · Popularity

What the whole community engages with right now. Also solves the cold-start problem for brand-new users.

default weight 20%
After blending: remove items already bought or dismissed · drop low scores · limit items per category (diversity) · attach a plain-English reason.
Runs in parallel: the three scorers execute on a thread pool (CompletableFuture), so a recommendation takes milliseconds.

Core Java concepts

OOP · Collections · Exceptions · Threads

Object-oriented design

  • Interface + polymorphism: Scorer with three implementations (Strategy pattern)
  • Inheritance: ApiServlet base class for 10 servlets
  • Encapsulation: records and a validating RecommendationSettings
  • Enums with behaviour: InteractionType, RecOutcome

Collections

  • HashMap / LinkedHashMap for profiles and vectors
  • PriorityQueue - bounded top-10 neighbours
  • Set / LinkedHashSet for exclusions and tags
  • TreeMap, streams and Comparator chains
  • ConcurrentHashMap for login throttling

Exception handling

  • Custom hierarchy: Validation · Authentication · Forbidden · NotFound · Conflict · DataAccess
  • One central handler turns them into JSON errors with the right HTTP status
  • try-with-resources and transaction rollback

Threads & concurrency

  • ExecutorService + CompletableFuture: scorers run in parallel with a timeout
  • ScheduledExecutorService housekeeping job
  • Immutable context object, volatile settings cache
Pulse · AI-Based Recommendation System18
Database & web integration

JDBC transactions, Servlets and sessions

JDBC

  • 9 tables with PK, FK, CHECK, UNIQUE, indexes, ON DELETE CASCADE
  • CRUD through PreparedStatement (no SQL injection)
  • Connection pool and batch inserts
  • Transactions (commit / rollback): registration, preference update, interaction + log, reviews, settings
  • Aggregate GROUP BY analytics queries

Servlets & sessions

  • 10 servlets: GET / POST / PUT / PATCH / DELETE with JSON and proper status codes
  • HttpSession: new session id at login (fixation defence), 30-minute timeout, HttpOnly cookie
  • Filters: AuthFilter (login + admin role) and security headers (CSP, nosniff)
  • Front-end talks to the servlets with fetch()
SecurityPBKDF2 hashing with salt · constant-time compare · login lock after 5 failures · server-side validation · XSS-safe UI (no innerHTML with data)
